# 客户端云功能

## 入口和分工

- 左侧栏 → **更多**：网盘、资料库、MCP / Skills 下载、云端定时任务。
- 已打开目录的文件树 → **云存储**：弹出当前工作区的文件选择器，可跨子目录多选，确认后上传。
- 设置中已移除「服务」和旧的「云文档 / WebDAV 存储」入口；本地 AI、MCP、Agent 和控制面设置保留。
- 用户凭据由 Node 宿主保管，不写入渲染端或 localStorage。未登录时“更多”展示账号登录面板。

Java 负责身份、元数据、目录和排期；RustFS 保存对象字节；客户端宿主负责执行任务。
资料库第一版是文件型资料库，不包含解析、向量化或 RAG。

## RustFS 配置

`back/grey/compose.yaml` 提供 RustFS，默认暴露 9000 端口。
在 Java 服务的环境中配置：

```dotenv
GREY_S3_ENABLED=true
GREY_S3_ENDPOINT=https://files.example.com
GREY_S3_REGION=us-east-1
GREY_S3_ACCESS_KEY=<与 RustFS 相同的 access key>
GREY_S3_SECRET_KEY=<与 RustFS 相同的 secret key>
GREY_S3_BUCKET=greywork
GREY_S3_PATH_STYLE=true
GREY_AUTOMATION_ZONE=Asia/Shanghai
```

本机开发可使用 `http://127.0.0.1:9000`，compose 默认凭据为
`greywork / greywork-secret`；生产环境必须更换。compose 使用 `GREY_S3_ACCESS_KEY`
和 `GREY_S3_SECRET_KEY`，与应用配置同源。RustFS 的 endpoint 必须同时能被 **Java 服务和客户端宿主**
访问。不要使用只在容器网络内可解析的主机名，或远程服务器的 localhost。

上传路径：申请票据 → 宿主读取已授权工作区文件 → 预签名 PUT 到 RustFS → Java HEAD 校验 → ready。
Content-Type 和 Content-Length 绑定到签名；客户端默认 private。网盘使用 `kind=file`，
资料库使用 `kind=library`。大小上限取服务器配置和客户端 128 MiB 硬顶的较小值。
空文件允许上传；单次选择最多 100 个文件，串行上传，失败保留未完成选择供重试。
上传的票据、PUT、确认和失败清理绑定同一宿主会话。换号或断开连接会取消在途请求，
已取得票据的清理仍使用原会话；若原凭据已被撤销，留给服务端过期上传清理，不会使用新账号的凭据。
列表显示最近 200 个对象，支持文件名筛选、下载和删除。删除云端对象不会删除本地文件。

预签名下载带 attachment 文件名，通过系统浏览器下载。客户端宿主直传无需浏览器端跨域 PUT，
也不向客户端分发 RustFS 长期密钥。所有对象操作都验证用户归属，跨用户访问返回 404。

## 云端定时任务

任务定义保存在 Java 数据库，不再由 `/scheduled` 本地页面管理；该地址重定向到 `/more/tasks`。
对话中的 schedule 提案会先进入云端编辑器，选定设备、离线策略并保存成功后，才标记“已创建”。
提交绑定原编辑器和提案回调；页面切换后晚到的结果只确认原提案，不会清空或关闭另一条提案。
旧的本地自动化数据仍保留，不自动删除或未经确认批量上传；已有任务需在云端重新确认配置。

每条任务独立选择：

- `offlinePolicy=replay`：默认。到期写入队列，设备上线后逐条补跑。
- `offlinePolicy=skip`：触发时没有符合设备绑定的在线执行器，则记 skipped，不在上线后补跑。

“在线”指最近 90 秒有宿主心跳，不是窗口必须处于前台。`hostDeviceId` 可以绑定设备，
也可为空让同账号任意设备认领；条件更新确保同一队列项不会同时被两个设备认领。
跳过策略判定在触发时进行：若设备触发时在线但随后断线，已入队项仍按租约机制恢复。

服务器通过认证的 SSE `/api/hosts/me/automation/events` 发出 `due` 唤醒信号。
通知不携带执行内容，客户端仍必须认领队列。SSE 连接每分钟结束并重新鉴权，
客户端自动重连，30 秒轮询作为断线/旧服务器的兜底。
反向代理需关闭该接口缓冲并放行流式响应；不支持 SSE 时仍能轮询执行。

执行器一次认领一条，避免多条串行任务提前占用并耗尽租约；通知、轮询和手动同步共用互斥锁。
租约默认 30 分钟，执行超时默认 25 分钟。完成后回传状态、详情和模型输出，页面可查看最近 50 次结果。
停用/删除任务取消尚未认领的队列项，不中断已在执行中的请求。

**当前执行范围**：客户端宿主对本机 OpenAI 兼容模型发起单轮请求，无工具、无 ACP。
任务可以指定模型，也可使用设备默认模型。Anthropic 原生协议及 ACP 任务不支持此执行器；
客户端不会默默改写已有云端/ACP 任务的执行配置。
排期使用服务器返回的时区，一次性时间输入明确标出该时区。

投递采用 **至少一次** 语义：客户端完成后若回执丢失，租约回收可能导致重跑。
不能把认领互斥理解成跨故障的“恰好一次”；有外部副作用的执行器需要自己的幂等键。

## MCP / Skills 下载

“更多”直接读取当前服务器的能力目录，不需要手动添加源。
Skills 支持 ZIP 下载和安装到当前工作区，安装前要求确认，仍走宿主的两阶段落盘校验。
云端和市场安装共用技能 store 的落盘、busy 状态和安装记录；保存 ref/hash/来源，后续更新仍从原来源下载。
MCP 支持下载 JSON 配置和预填添加表单；新添加项默认停用，密钥由用户在本机补充。
MCP 的 npm / PyPI 进程在启用后由本机启动，并非将可执行程序存放在服务器上运行。
管理员继续通过运维台「能力目录」上架/编辑内容。

## 接口变化

- 上传请求新增可选 `kind`；对象列表新增 `kind=file|library` 筛选。
- 上传票据、对象、投递、运行记录与设备绑定 ID 按字符串返回，避免 JS Long 精度损失。
- 任务输入/输出新增 `offlinePolicy`，缺省 replay；V14 自动迁移已有任务。
- `GET /api/automation/tasks/config` 返回 `zone` / `tickMs`。
- `GET /api/hosts/me/automation/events` 是需要登录并已注册宿主的 SSE。
- 宿主新增 `cloud_request`、`cloud_upload_file`，请求代理仅允许明确的用户接口，不允许管理接口或任意 URL。
